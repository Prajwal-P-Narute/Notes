🍪 48. Cookies
What are Cookies? Small key-value pairs stored by the browser per origin. Used for sessions, auth tokens, user prefs. Playwright lets you fully control the cookie jar on BrowserContext.
➕ Add Cookies
// Add cookies to the context before navigation await context.addCookies([ { name: 'auth_token', value: 'abc123xyz', domain: 'example.com', path: '/', httpOnly: true, secure: true, expires: Date.now() / 1000 + 3600 // 1 hour } ]);
📖 Read Cookies
// Get all cookies const allCookies = await context.cookies(); // Get cookies for a specific URL const siteCookies = await context.cookies('https://example.com'); // Find a specific cookie const token = siteCookies.find(c => c.name === 'auth_token'); console.log(token.value);
🗑️ Delete / Clear Cookies
// Clear ALL cookies in the context await context.clearCookies(); // Delete specific cookies (overwrite with expired cookie) await context.addCookies([{ name: 'auth_token', value: '', domain: 'example.com', path: '/', expires: 1 // expired — effectively deletes it }]);
✏️ Modify Cookies
  • Playwright has no direct "update cookie" API — read → modify → re-add
  • Use clearCookies() + addCookies([...]) with updated value
  • Or just call addCookies() with same name — it overwrites the existing one
💡 Cookie Workflow Tip Set cookies before page.goto() to skip the login UI entirely. Grab real cookies by running the login once → context.cookies() → save to JSON → reuse in future tests.
⚠️ Domain Gotcha Cookie domain must match the actual site domain exactly. Leading dot (.example.com) makes it available on all subdomains. Missing domain = cookie silently ignored.

In Playwright, I manage browser cookies through the BrowserContext API rather than through page-level methods.

💾 49. Local Storage
What is Local Storage? A browser-side key-value store (origin-scoped, no expiry). Unlike cookies it's never sent to the server. Playwright can read/write it via page.evaluate() since it's a JS API.
✍️ Set Local Storage
await page.evaluate(() => { localStorage.setItem( 'userTheme', 'dark' ); });
📖 Read Local Storage
const theme = await page.evaluate(() => localStorage.getItem('userTheme') ); console.log(theme); // 'dark'
🧹 Clear / Remove Storage
// Remove one item await page.evaluate(() => localStorage.removeItem('userTheme')); // Clear everything in localStorage await page.evaluate(() => localStorage.clear()); // Inject storage state BEFORE page load via storageState const context = await browser.newContext({ storageState: 'auth.json' // saved session (cookies + localStorage) });
📝 storageState — The Power Move page.context().storageState({ path: 'auth.json' }) saves both cookies AND localStorage in one file. Load it in newContext({ storageState: 'auth.json' }) to restore a full authenticated session instantly.
📍 50. Geolocation
🔐 Grant Location Permission + Set Fake GPS
// Grant geolocation permission + set a fake GPS location const context = await browser.newContext({ permissions: ['geolocation'], geolocation: { latitude: 19.0760, longitude: 72.8777 } // Mumbai }); // OR — update location mid-test await context.setGeolocation({ latitude: 28.6139, longitude: 77.2090 }); // Delhi // Grant permission AFTER context is created await context.grantPermissions(['geolocation']); // Revoke permissions await context.clearPermissions();
💡 Real-World Use Test location-based features (store locators, delivery radius, language auto-detect) without physically moving. Combine permissions + geolocation in newContext() for one-shot setup.

🔒 51. Permissions
Permission Types Playwright can grant or deny browser permissions programmatically — no popups, no manual "Allow" clicks needed.
Permission StringWhat It ControlsCommon Test Scenario
'notifications'Push notification promptsTest notification banner, subscription flow
'camera'Camera access (getUserMedia)Video call, photo upload UI
'microphone'Microphone accessVoice input, recording features
'geolocation'GPS / location APIStore locator, maps, delivery
'clipboard-read'Clipboard pasteCopy-paste text validation
'clipboard-write'Clipboard write"Copy link" button tests
Grant Permissions
// Grant multiple permissions at once await context.grantPermissions([ 'notifications', 'camera', 'microphone' ]); // Grant for a specific origin only await context.grantPermissions(['notifications'], { origin: 'https://app.example.com' }); // Deny / revoke all permissions await context.clearPermissions();
Grant via newContext() — preferred pattern
const context = await browser.newContext({ permissions: ['camera', 'microphone'] });
⚠️ Gotcha grantPermissions only works for permissions the browser natively supports via the Permissions API. Some permissions (e.g. 'clipboard-read') may require page.evaluate() workarounds in older Chromium builds.
🔑 52. HTTP Authentication
Basic Auth HTTP Basic Auth = browser shows a native login dialog (not a web form). Pass credentials to newContext() and Playwright sends them in every request automatically.
// Supply HTTP Basic Auth credentials on context creation const context = await browser.newContext({ httpCredentials: { username: 'admin', password: 'secret123' } }); const page = await context.newPage(); await page.goto('https://protected.example.com'); // no popup!
Alternative — URL credentials (quick hack)
// Embed credentials in the URL — works but is not recommended in prod await page.goto('https://admin:secret123@protected.example.com');
✅ Best Practice Always use httpCredentials in newContext(). Never hardcode real passwords — pull from process.env or a .env file.
📝 Difference HTTP Basic Auth ≠ Form-based login. Basic Auth = browser dialog. Form login = HTML form. Use httpCredentials only for Basic Auth.
💬
🗣️ How I'd say it in an interview
❓ Interviewer asks:How do you handle browser permissions and HTTP Basic Authentication?

For browser permissions, I configure the required permission on the browser context so tests do not depend on manual prompts.

For example, I can create a context with permissions: ['camera'] or grant permissions through context.grantPermissions().

For location-based tests, I combine the geolocation permission with configured coordinates to simulate a device location.

To reset permission state, I use context.clearPermissions() when the next scenario needs a clean setup.

For HTTP Basic Auth, I pass the username and password through the httpCredentials option when creating the context.

That is different from form-based login, where I interact with username and password fields in the application's page.

For safe configuration, I keep real credentials in environment variables rather than hardcoding them into test files.

So, in short, I configure browser permissions and HTTP credentials at the context level to keep setup controlled and tests reliable.

Playwright — Phase 15Proxy · Downloads
🌐 53. Proxy
Proxy Route all Playwright traffic through an intermediary server. Useful for: corporate networks, traffic inspection, geo-routing, mocking external APIs.
🔧 Proxy Configuration
// Set proxy for the entire browser launch const browser = await chromium.launch({ proxy: { server: 'http://proxy.company.com:8080' } }); // OR — set proxy per BrowserContext (more granular) const context = await browser.newContext({ proxy: { server: 'http://proxy.company.com:8080', bypass: 'localhost,127.0.0.1' // skip proxy for these } });
🔐 Proxy Authentication
const context = await browser.newContext({ proxy: { server: 'http://proxy.company.com:8080', username: 'proxyuser', password: 'proxypass' } });
💡 SOCKS5 Proxy server: 'socks5://proxy:1080' — Playwright supports HTTP, HTTPS, and SOCKS5 proxy protocols.
📝 bypass Comma-separated list of hosts that skip the proxy. Always bypass localhost to avoid routing local dev traffic through the proxy.
⬇️ 54. Downloads
Download Flow Playwright intercepts downloads via a Download event. The file is held in a temp path until you move or read it. Downloads don't open a native "Save As" dialog in headless mode.
📥 Capture a Download
// Wait for download to start while clicking the trigger const [download] = await Promise.all([ page.waitForEvent('download'), // set up listener FIRST page.click('#download-btn') // then trigger ]); // Get temp path (auto-cleaned up after test) const tmpPath = await download.path(); // Save to a permanent location await download.saveAs('./reports/exported.csv'); // Get original filename from server const filename = download.suggestedFilename();
✅ Validate Downloaded File
import * as fs from 'fs'; const savePath = './downloads/report.pdf'; await download.saveAs(savePath); // Check file exists expect(fs.existsSync(savePath)).toBe(true); // Check file size is non-zero const stats = fs.statSync(savePath); expect(stats.size).toBeGreaterThan(0); // Check file name expect(download.suggestedFilename()).toBe('report.pdf');
⚠️ Critical — Order Matters! Always put waitForEvent('download') before the click action in Promise.all. If you click first, the download may start and finish before the listener is set up → missed event → test hangs forever.

Playwright — Phase 15Uploads · File Chooser
⬆️ 55. Uploads & File Chooser
Upload Strategies Playwright provides two ways to handle file uploads: direct input fill (simplest) and file chooser interception (for hidden inputs or custom upload UIs).
📄 Single File Upload (setInputFiles)
// Simplest — directly set the file on an input element await page.setInputFiles('input[type="file"]', './fixtures/resume.pdf'); // Then submit the form await page.click('#upload-submit');
📂 Multiple File Upload
// Pass an array of file paths await page.setInputFiles('input[type="file"]', [ './fixtures/photo1.jpg', './fixtures/photo2.jpg', './fixtures/document.pdf' ]); // Clear previously selected files await page.setInputFiles('input[type="file"]', []); // empty array = clear
🗂️ File Chooser Interception
Used when the file input is hidden / triggered by a custom button (drag-and-drop zones, styled upload buttons, etc.). Intercept the filechooser event.
// Intercept the file chooser BEFORE the triggering click const [fileChooser] = await Promise.all([ page.waitForEvent('filechooser'), // listener first! page.click('#upload-area') // trigger second ]); // Set single file await fileChooser.setFiles('./fixtures/logo.png'); // Set multiple files await fileChooser.setFiles(['./file1.png', './file2.png']); // Check if multiple files are allowed const isMultiple = fileChooser.isMultiple(); // returns boolean
⚡ Upload from Buffer (no file on disk)
// Create a virtual file from in-memory buffer await page.setInputFiles('input[type="file"]', { name: 'generated.txt', mimeType: 'text/plain', buffer: Buffer.from('Hello, this is file content!') });
MethodWhen to UseKey Difference
setInputFiles(selector, path)Visible <input type="file">Direct, simplest
waitForEvent('filechooser')Hidden input, custom upload buttonIntercepts OS dialog
setInputFiles(..., buffer)Generate file data in-memoryNo actual file needed
🎤
🗣️ How I'd say it in an interview
❓ Interviewer asks:How do you automate file uploads in Playwright?

For a standard upload, I use page.setInputFiles() with the file input locator and the path to the fixture file.

For multiple files, I pass an array of paths when the input supports selecting more than one file.

When the input is hidden, I listen for the filechooser event and trigger the custom upload button in the same operation.

The important detail is to register page.waitForEvent('filechooser') before clicking so the event is not missed.

After the event arrives, I call fileChooser.setFiles() to provide the file or files to the chooser.

If no disk file is needed, I can pass an object containing a filename, MIME type, and buffer to setInputFiles().

After uploading, I assert the application's visible success state or other expected result rather than assuming selection means upload succeeded.

So, in short, I choose direct file assignment for ordinary inputs and event interception for custom upload controls.

TIER 3⚠️ Common Mistakes & Gotchas ALWAYS READ
  • Setting up waitForEvent('download') after the click — download fires before listener → test hangs forever
  • Missing domain in addCookies() — cookie is silently rejected, auth fails with no error
  • Calling page.evaluate(localStorage...) before the page has navigated — localStorage is empty, set fails silently
  • Passing permissions inside browser.launch() — permissions only work on BrowserContext, not browser-level
  • Using httpCredentials for form-based logins — it only handles the HTTP Basic Auth browser dialog, not HTML login forms
  • Forgetting proxy.bypass: 'localhost' — local dev server traffic routes through proxy → connection refused
  • Calling setInputFiles(selector, []) to clear doesn't always trigger the change event — may need explicit dispatch
  • Assuming download.path() persists — temp file is deleted after test ends; use saveAs() immediately
  • Not granting geolocation permission before calling setGeolocation() — coordinates are ignored silently

⬇️⬆️ "L before C"
Listener before Click — always. For both download and filechooser events. Set the net before throwing the stone.
💾 storageState = "Save Game"
Login once → save the "game state" → load it in every new test. Cookies + localStorage both saved. The ultimate session shortcut.
🔑 HTTP Auth ≠ Form Login
If the browser shows a grey native dialog box → HTTP Basic Auth → use httpCredentials.
If it's a styled HTML page → use Playwright actions.
  • Last-minute tip: Always pull credentials from process.env, never hardcode in test files
  • Last-minute tip: In CI, save storageState as an artifact and reuse across test suites — huge speed win
  • Last-minute tip: Test geolocation-dependent features with multiple coordinate sets — your app may break at edge coordinates
  • Last-minute tip: For download validation, check both file existence AND size > 0 — an empty file often means a network error not caught by the download event
